# 家居产业前台展示调整设计方案

## 背景

本次调整针对家居产业/增值服务前台页面，涉及：

- 首页：`/homeIndustry`
- 模块详情页：`/homeIndustry/:moduleCode`

最新设计稿确定了新的信息组织方式：

1. 首页需要按“家居产业链服务”和“利企配套服务”分区展示。
2. 详情页需要采用“左侧导航 + 右侧卡片详情”的信息结构。
3. 家居产业链服务详情需要突出“上游 / 中游 / 下游”的业务链路。

用户已明确要求：本次只调整前台展示，不改后台、不改接口、不改数据库；布局参考设计稿，但不能直接照搬设计稿中的紫灰底、粗蓝框、线框按钮等视觉样式，整体视觉继续沿用项目当前前台的蓝白渐变、圆角卡片、阴影和 hover 动效。

## 目标

- 让前台页面的信息结构接近最新设计稿。
- 保持当前项目已有视觉风格，避免设计稿线框化、粗边框化的效果。
- 复用现有接口和后台数据结构，保证已有内容、链接节点、区块内容继续可用。
- 尽量做最小化前端改动，降低回归风险。

## 非目标

- 不新增后台配置项。
- 不修改数据库结构。
- 不修改后端接口。
- 不重新设计整套 UI 主题。
- 不强制清洗或重建现有内容数据。

## 当前实现概览

相关文件：

- `frontend/src/pages/home-industry/HomeIndustryHomePage.jsx`
  - 当前首页直接读取公开模块列表并以三列卡片展示。
  - 使用 `getCdModules()` 和 `getCdPublicSettings()`。
  - 使用 `historic.css` 中的 `.hd-page`、`.hd-hero`、`.hd-card-grid`、`.hd-card-link` 等样式。

- `frontend/src/pages/home-industry/ModuleDetailPage.jsx`
  - 当前详情页读取模块树并渲染左侧菜单和右侧内容。
  - 已兼容嵌套内容和扁平内容字段。
  - 已兼容 `link`、`info`、`richtext`、`blocks` 等内容类型。

- `frontend/src/styles/historic.css`
  - 家居产业前台复用历史城区样式体系。
  - 当前视觉为蓝白主色、渐变导航、圆角卡片、阴影和响应式布局。

## 设计原则

1. 布局参考设计稿，视觉沿用现有风格。
2. 前台只做展示层适配，数据来源仍使用现有公开接口。
3. 链接节点继续作为直接跳转入口，不强制生成下级详情页。
4. 有内容的节点继续走详情卡片展示，兼容历史数据。
5. 保持响应式能力，桌面端优先还原设计稿布局，窄屏退化为单列展示。

## 首页设计

### 信息结构

首页主体从“单一模块卡片列表”调整为“两组服务入口”：

1. 家居产业链服务
   - 上游：原辅料采购、仓储
   - 中游：生产制造
   - 下游：销售出海

2. 利企配套服务
   - 财税服务
   - 人力资源服务
   - 项目施工服务
   - 中介服务

### 交互规则

- 如果入口对应现有模块，则点击进入 `/homeIndustry/:moduleCode`。
- 如果入口对应树中的链接节点，则点击后直接打开链接。
- 如果暂时无法匹配到具体数据，则入口仍展示，但使用禁用/弱提示状态，避免空跳转。
- 保持顶部导航与 Banner 逻辑不变，继续读取后台设置的首页 Banner。

### 视觉规则

- 保留现有顶部导航和 Banner 风格。
- 分组标题使用现有蓝色主色和装饰风格，不使用设计稿中的粗蓝色块。
- 服务入口使用现有卡片按钮风格：圆角、浅蓝背景、细边框、hover 阴影。
- 桌面端产业链服务优先三列展示，利企配套服务优先四列展示；窄屏自动换行。

## 详情页设计

### 通用详情页结构

详情页保留：

- 顶部导航
- Banner/标题区
- 主体内容区
- 回到顶部按钮
- 页脚

主体内容区继续使用“左侧导航 + 右侧内容”的结构，但视觉和内容密度向设计稿靠拢：

- 左侧导航展示阶段、分类、条目。
- 右侧按阶段和分类渲染内容卡片。
- 卡片内展示服务内容、服务地点、提供部门、办公时间、咨询电话、线上申报入口等字段。

### 招商入驻及配套服务类模块

适用于：

- 招商入驻
- 项目服务
- 政策服务
- 法律服务
- 人才服务
- 金融服务
- 帮办服务
- 国际贸易服务
- 其他同类前台模块

展示方式：

- 左侧为树结构导航。
- 右侧按节点顺序展示内容卡片。
- 链接型叶子节点保持直接跳转按钮。
- 富文本/区块内容继续使用现有内容渲染能力。

### 家居产业链服务模块

适用于产业链类数据：

- 上游：原辅料采购、仓储
- 中游：生产制造
- 下游：销售出海

展示方式：

- 左侧突出“上游 / 中游 / 下游”层级。
- 右侧按链路阶段展示服务卡片。
- 服务卡片使用项目当前视觉风格，不使用设计稿粗边框样式。

## 数据兼容设计

继续兼容现有两类数据形态：

1. 嵌套内容：

```js
node.content = {
  content_type,
  summary,
  department,
  remark,
  link_url,
  link_label,
  link_target,
  body,
  fields
}
```

2. 扁平内容：

```js
node = {
  content_type,
  summary,
  department,
  remark,
  link_url,
  link_label,
  link_target,
  body,
  fields,
  children
}
```

兼容规则：

- `content_type='link'` 且存在 `link_url` 时继续渲染为可点击链接。
- `content_type='blocks'` 时继续解析 JSON 区块内容，解析失败降级为纯文本。
- `content_type='info'` 但存在 `body` 且字段为空时继续按富文本兜底。
- 标题和正文完全重复的叶子节点继续只显示正文，避免重复标题栏。

## 样式设计

本次不照搬设计稿视觉，只做布局参考。样式应延续：

- 主色：当前蓝白体系。
- 组件：圆角卡片、细边框、渐变背景、轻阴影。
- 交互：保留 hover 过渡和轻微阴影变化。
- 布局：桌面端左右分栏，移动端上下堆叠。

可新增少量语义化 class，用于区分：

- 首页分组容器。
- 首页服务入口卡片。
- 详情页服务卡片。
- 产业链阶段块。

新增样式应写在 `frontend/src/styles/historic.css` 中，避免引入新的样式文件。

```bash
npm run build
```

重点回归：

- `frontend/src/tests/module-detail-link.test.jsx`
- `frontend/src/tests/module-detail-body-fallback.test.jsx`

- 链接型入口仍可直接跳转。
- 模块入口仍可进入详情页。

## 风险与控制

### 风险一：模块标题或编码与设计稿入口不完全一致

控制方式：优先基于现有模块 `code` 匹配；必要时对标题做宽松匹配；无法匹配时展示弱提示状态，不影响页面整体可用。

### 风险二：历史数据层级不完全符合“上游 / 中游 / 下游”

控制方式：详情页仍以接口返回的树结构为准，只在前台展示层做分组和样式优化，不强行重塑数据。

### 风险三：现有测试数据存在中文编码显示异常

控制方式：本次不主动重编码无关文件；只在必要修改处保持 UTF-8 输出，并通过测试和构建确认运行结果。
